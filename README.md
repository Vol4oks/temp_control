# temp_control

Прошивка для **ESP32-C6** на Rust (`std` через `esp-idf-svc`): опрос датчика
DHT11, вывод показаний на OLED SSD1306, Wi-Fi с веб-интерфейсом (показания,
графики истории, двухточечная калибровка через браузер, настройка NTP-сервера)
и историей измерений в NVS.

## Возможности

- ✅ **`sensor_task`** — опрос DHT11 каждые 2 сек; ошибки чтения (таймаут/CRC)
  логируются; рассылка в каналы подписчиков (экран, веб, логгер)
- ✅ **`display_task`** — SSD1306 по I2C (400 кГц), раз в 1 сек: T/H крупно +
  IP-адрес устройства
- ✅ **Wi-Fi STA** — подключение по данным из `secrets.toml`, фоновый
  keepalive: переподключение при потере связи, обновление IP
- ✅ **Веб-интерфейс** (HTTP, порт 80) — живые показания (опрос раз в 2 сек),
  графики истории T и H, калибровка перетаскиванием точек по сетке,
  настройка NTP-сервера
- ✅ **Двухточечная калибровка** — `real = k·measured + b` по двум парам
  «показал → реально» для T и H; применяется в `sensor_task`; хранится
  в NVS (приоритет) поверх `config.toml`; сброс к конфигу через веб
- ✅ **История** — среднее за 5 минут, 288 точек = 24 часа; кольцо в RAM,
  бинарный снапшот в NVS раз в час; восстанавливается после перезагрузки
- ✅ **SNTP** — реальное время (ось графика); NTP-сервер меняется через веб
  и хранится в NVS (приоритет) поверх `config.toml`
- ✅ **Supervisor** — смерть любого фонового потока: лог + перезагрузка
  устройства

План на будущее (lib-таргет с хост-тестами, расширение NVS-раздела) —
в [docs/PLAN.md](docs/PLAN.md); открытые вопросы —
[docs/QUESTIONS.md](docs/QUESTIONS.md).

## Железо

| Что | Пин | Примечание |
|-----|-----|------------|
| DHT11 DATA | GPIO4 | open-drain + подтяжка вверх (внутренняя; «голому» сенсору нужен внешний резистор 4.7–10 кОм) |
| SSD1306 SDA | GPIO6 | I2C, адрес 0x3C |
| SSD1306 SCL | GPIO7 | I2C, 400 кГц |

Дисплей 128×64. GPIO4–7 на ESP32-C6 — пины внешнего JTAG: с этой разводкой
внешний JTAG-отладчик работать не будет (прошивка через USB не страдает).

## Быстрый старт

### 1. Окружение

- Rust nightly с таргетом `riscv32imac-esp-espidf` и `rust-src`
  (ставится через [espup](https://github.com/esp-rs/espup): `cargo install espup && espup install`)
- [ldproxy](https://github.com/esp-rs/embuild): `cargo install ldproxy`
- Активация окружения перед сборкой (fish):

  ```fish
  source $HOME/export-esp.sh
  ```

ESP-IDF v5.5.3 скачивается автоматически при первой сборке в `.embuild/`
внутри проекта (`ESP_IDF_TOOLS_INSTALL_DIR = "workspace"`).

### 2. Секреты Wi-Fi

```fish
cp secrets.toml.example secrets.toml
```

и заполните `ssid` / `password`. Файл в `.gitignore`, в git не попадает.
Без `secrets.toml` сборка падает с подсказкой (проверка в `build.rs`).

### 3. Сборка и прошивка

```fish
cargo build          # первая сборка долгая: toolchain + ESP-IDF
cargo run            # = cargo espflash flash --monitor
```

Логи при старте: конфигурация, пины, интервалы, Wi-Fi/IP, SNTP-синхронизация,
затем измерения и точки истории.

### 4. Веб-интерфейс

Откройте **`http://<IP устройства>/`** — только HTTP (HTTPS-режим браузера
нужно отключить для этого адреса). Адрес виден в логе при подключении и
на дисплее устройства.

Проверки кода:

```fish
cargo check
cargo clippy --all-targets
cargo fmt --all -- --check
```

Таргет указывать не нужно — он задан в `.cargo/config.toml`.

При проблемах с зависимостями: `cargo clean && rm -f Cargo.lock`.

## Веб-интерфейс и API

| Эндпоинт | Описание |
|----------|----------|
| `GET /` | страница: показания (2 сек), графики истории (1 мин), калибровка, SNTP |
| `GET /api/temperature` | последнее измерение: T/H + `raw_*` + uptime + IP |
| `GET /api/history` | `{point_secs, points: [{temperature, humidity, uptime_secs, unix_secs}]}` |
| `GET /api/calibration` | активные точки + источник (`nvs` \| `config`) |
| `POST /api/calibration` | `{temperature: {point1, point2}, humidity: {...}}` → валидация → NVS → применение |
| `POST /api/calibration/reset` | сброс калибровки к `config.toml` |
| `GET /api/sntp` | текущий NTP-сервер + источник |
| `POST /api/sntp` | `{"server": "..."}` → NVS → перезапуск клиента (до 10 сек) |
| `POST /api/sntp/reset` | сброс NTP-сервера к `config.toml` |

Для калибровки и NTP-сервера действует приоритет **NVS (веб) > `config.toml`**.
До синхронизации времени точки истории имеют `unix_secs = 0` — ось графика
в этом случае показывает «N минут назад».

## Настройки (`config.toml`)

| Секция | Ключ | По умолчанию | Описание |
|--------|------|--------------|----------|
| `[pins]` | `dht11_data` | `4` | GPIO линии DATA DHT11 (0–30) |
| | `i2c_sda` / `i2c_scl` | `6` / `7` | GPIO шины I2C дисплея |
| `[display]` | `i2c_address` | `0x3C` | I2C-адрес SSD1306 |
| | `width` / `height` | `128` / `64` | разрешение; поддерживается только 128×64 |
| `[intervals]` | `sensor_poll_secs` | `2` | период опроса DHT11 (не чаще ~1 Гц) |
| | `display_refresh_secs` | `1` | период обновления экрана |
| | `history_point_secs` | `300` | окно усреднения истории (точка раз в 5 мин) |
| | `history_save_secs` | `3600` | снапшот кольца истории в NVS (раз в час) |
| `[history]` | `max_points` | `288` | глубина истории: 288 × 5 мин = 24 часа |
| `[calibration]` | `measured_1` / `real_1` | `0.0` / `0.0` | опорная точка 1: показал → реально |
| | `measured_2` / `real_2` | `1.0` / `1.0` | опорная точка 2 |
| `[sntp]` | `server` | `"pool.ntp.org"` | NTP-сервер (переопределяется через веб) |

Секция `[calibration]` (подробности — ОВ-6 в docs/QUESTIONS.md):

- задаётся отдельно для `[calibration.temperature]` и `[calibration.humidity]`
- по умолчанию — идентичность (значения проходят без изменений); секцию
  можно удалить целиком
- чистый сдвиг — частный случай (например, `0→2` и `10→12` даёт +2 °C)
- точки снимайте в заметно разных условиях: близкие `measured_*` дают
  нестабильный наклон
- калибровку удобно задавать через браузер: сырые значения видны на
  странице и в `/api/temperature`

## Секреты (`secrets.toml`)

```toml
[wifi]
ssid = "MyNetwork"
password = "MyPassword"
```

Используются задачей Wi-Fi (WPA2). Файл в `.gitignore`, в git не попадает;
без него сборка падает с понятным сообщением (проверка в `build.rs`).

## Структура проекта

```
src/
├── main.rs          # запуск задач, раздача периферии, supervisor потоков
├── config.rs        # парсинг config.toml + secrets.toml (serde)
├── pins.rs          # номера GPIO из конфига → handle'ы (единственный unsafe)
├── sensor.rs        # sensor_task: опрос DHT11, рассылка в каналы
├── calibration.rs   # двухточечная калибровка (валидация + пересчёт)
├── display.rs       # display_task: SSD1306 через embedded-graphics
├── net.rs           # Wi-Fi STA + keepalive + SNTP (клиент и смена сервера)
├── history.rs       # logging_task: усреднение, кольцо, снапшот THS2
├── storage.rs       # NVS: калибровка (JSON), история (блоб), sntp_server
├── web.rs           # HTTP-сервер: страница + JSON API
└── web/index.html   # страница (запекается в прошивку, без внешних CDN)
```

Поток данных: `sensor_task` → mpsc-каналы → `display_task`, `web_pump`
(последнее измерение для API) и `logging_task` (усреднение → кольцо →
снапшот). Калибровка и SNTP-сервер — общие состояния `Arc<Mutex<…>>`:
сенсор/keepalive читают, веб-хендлеры меняют. Смерть любого потока →
перезагрузка устройства (supervisor).

Износ флеша: усреднение 5 мин + снапшот раз в час ≈ 5–6 КБ записи в час —
ресурс NVS измеряется десятилетиями (расчёт — ОВ-3 в docs/QUESTIONS.md).

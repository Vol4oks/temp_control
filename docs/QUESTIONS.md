## ОВ-3. История измерений в NVS — ✅ решён

Решение (2026-09-25, подтверждено пользователем): **усреднение за 5 минут**.

- Точка истории = среднее за окно 300 сек (≈150 замеров); окно закрывается
  по числу замеров — молчит датчик, окно не закрывается (пробел в истории)
- Глубина: 288 точек × 5 мин = 24 часа; кольцо в RAM (~3.4 КБ)
- `logging_task` — третий подписчик канала; снапшот кольца в NVS раз в час,
  бинарный блоб `THS1` + u32 count + записи f32/f32/u32 (~3.5 КБ — одна
  страница NVS)
- Ресурс флеша: десятки лет; при потере питания теряется ≤1 час истории
- После старта кольцо восстанавливается из снапшота
- `GET /api/history` — точки из RAM (JSON)
- Только среднее (min/max в точке не храним — можно добавить позже)

## ОВ-6. Калибровка DHT11 — ✅ подход решён

Решение (2026-09-23, Plan-ID: CAL1): двухточечная калибровка
`real = k·measured + b` через две пары «показал датчик → реально есть»,
отдельно для T и H.

- Конфиг: секция `[calibration]` в `config.toml` — реализовано (Этап 2.1)
- Браузер: интерактивная сетка с перетаскиваемыми точками + API + NVS — Этап 4
- Приоритет: NVS (браузер) > config.toml

Замечание по снятию точек: опорные точки брать в заметно разных условиях
(близкие measured дают нестабильный наклон). Сравнивать с эталонным
термометром; сырые значения видны в логе и будут в API (`raw_*`).
